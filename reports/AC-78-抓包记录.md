## 4. 抓包里的非回环流量是谁的

| `functional.events.data.microsoft.com` | 8 | **Windows 自身遥测** |

**云 OCR、Langfuse、Sentry、OpenTelemetry 等与本服务相关的域名：0 命中。**

需要写清两点：

1. `functional.events.data.microsoft.com` 是 **Windows 操作系统的遥测**，不是本服务的。本服务没有 telemetry SDK，也不发这条解析。

### 4.2 非回环目的地址

第一轮 76 个目的地址里，绝大多数是 `:443` 的 CDN/云服务连接，以及局域网地址

## 6. 局限（不影响本节判定，但必须写明）

| # | 局限 | 影响 |
|---|---|---|
| L1 | `--pkt-size 128` 只记每包前 128 字节 | 不能做全文 DPI；「载荷无条款正文」是抽样观察，不是全量比对 |
| L2 | `pktmon` 回环采样不完整：10 个 HTTP 请求只记到 6 个包，且完全没有 `19530` 的流 | 不能按请求做逐包字节核账；归属改用连接表（第 3 节）补足 |
| L3 | 整机抓包，`etl` 里没有 PID 字段 | 归属靠「本机端口 ∩ 连接表」，短命连接可能漏采（150 ms 间隔） |
| L4 | 未加 `-IncludeOcr`，本轮不含 OCR 出域流量 | OCR 通道证据仍只有 `egress_logs` 与代码路径，未做 OCR 抓包 |

结论的强度建立在一件事上：**后端进程在窗口内没有建立任何非回环连接**。只要这条成立，
「外发业务正文为 0」就成立——没有连接就没有载荷。L1～L3 影响的是「能细到什么程度」，不是这条结论本身。

## 8. 复现

```powershell
# 1. 抓包（需管理员；非管理员直接退出码 5）
powershell -ExecutionPolicy Bypass -File scripts\ac78_capture.ps1
#    产物：var\ac78.etl / var\ac78.txt（txt 为 UTF-16LE）

# 2. 连接级归属（与抓包同时跑）
$bePid = (Get-NetTCPConnection -LocalPort 8011 -State Listen).OwningProcess
Get-NetTCPConnection -OwningProcess $bePid |
  Select-Object LocalAddress,LocalPort,RemoteAddress,RemotePort,State

# 3. 出域台账
python -c "import sqlite3;c=sqlite3.connect('var/gips.db');print(list(c.execute('select state,dlp_verdict,count(*) from egress_logs group by 1,2')))"
```

脚本说明：`scripts/ac78_capture.ps1` 以 UTF-8 **带 BOM** 保存（Windows PowerShell 5.1 按 ANSI 读无 BOM 文件会把中文注释读成乱码并报语法错）；
`pktmon etl2txt` 的输出是 UTF-16LE，用 Python 解析时按 `encoding='utf-16'` 读，按 UTF-8 读会得到交错 `\x00` 的空结果。
