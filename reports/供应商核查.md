# 供应商核查（AC-76）

- 执行日期：2026-11-10
- 判据：`v1-spec/spec/验收标准.md` AC-76 —— 逐项核查供应商配置，memory、fine-tune、session、personalization 全部关闭，有配置导出
- 结论：**技术侧可核查项通过；合同条款证据缺项，且按上游契约属本期不验收范围**。不判「全部通过」，逐项见下表与第 4 节

---

## 1. 本期涉及哪些外部方

| 外部方 | 用途 | 是否出域 | 依据 |
|---|---|---|---|
| 阿里云 OCR（`ocr-api.cn-hangzhou.aliyuncs.com`，RecognizeGeneral） | 无文本层页面识别，主供应商 | **是**，只出页面裁边图像 | R-47、CT-11 |
| 腾讯云 OCR（`ocr.tencentcloudapi.com`，GeneralBasicOCR） | 第二供应商，主供应商失败时换用 | **是**，同上 | R-47、CT-11 |
| 生成模型 | Qwen3-8B GGUF，**本机 llama.cpp 推理** | 否 | R-46、PRD 4.2 |
| 嵌入 / 重排 | `bge-m3`、`bge-reranker-v2-m3`，本机推理 | 否 | R-13、R-26 |
| Langfuse / 遥测 | 本期未部署 | 否 | R-5、R-38 |

结论先说清楚：**本系统不是「零外发」**。有文本层的 PDF 全程不出域（R-47），
无文本层页面会经出域网关送云 OCR，这是设计内的显式通道，每次出域都落 `egress_logs`。

## 2. 逐项配置核查

### 2.1 memory / session / personalization

| 检查项 | 结论 | 证据 |
|---|---|---|
| 供应商侧是否开启会话记忆 | 不适用（接口无此能力） | `app/parse/ocr/aliyun.py`：请求体为 `RecognizeGeneralRequest(body=BytesIO(image_bytes))`，只有图像；`app/parse/ocr/tencent.py`：只有 `ImageBase64`。两家 OCR 接口都不提供 memory / session / personalization 参数，客户端也没有可开的开关 |
| 跨请求留存 | 不适用（同上） | 同上；网关侧另有进程内幂等缓存（`EgressGateway._cache`，键=doc+版本+页码+裁边框），只避免重复计费，不向供应商传标识 |
| personalization | 不适用 | 请求中无任何用户/机构标识字段，供应商拿不到「为谁服务」的上下文 |

> 「不适用」写在这里不是免责：它成立的前提是**只用 OCR 接口、不接任何对话类外部模型**。
> 一旦二期接入外部生成模型，这一节必须按 PRD 第 9 章逐项重做，不能沿用本结论。

### 2.2 fine-tune / 语料外流训练（R-44）

| 检查项 | 结论 | 证据 |
|---|---|---|
| 是否用本项目语料微调或蒸馏 | 否 | 仓库内无训练/微调流水线；`models/` 下为第三方权重直接推理；`app/core/llm.py` 只做加载与生成 |
| 供应商侧自动微调 | 不适用 | 只用 OCR，不提供训练反馈入口 |
| 请求头 `X-No-Retention` | **未实现** | 契约 2.3 要求出域请求带 `X-No-Retention: true`，当前 OCR SDK 调用未带该头（见第 4 节 GAP-V-01） |

### 2.3 出域控制（技术侧证据）

| 控制 | 实现 | 可核证据 |
|---|---|---|
| 有文本层不送 OCR | `DocumentRouter.parse` 先检测文本层，`has_text_layer` 直接走文本抽取 | `app/parse/router.py`；本次 146 页重建全程 `used_ocr=false` |
| B 类必须审批 | `corpus_type=B_internal` 且无 `approval_ref` → `OCR_APPROVAL_MISSING`，不发请求 | `app/core/egress.py` 规则 1，单测覆盖 |
| C 类永久禁止 | `C_ledger` → `OCR_FORBIDDEN_CORPUS`，连日志都不写 | `app/core/egress.py` 规则 2 |
| 裁边预处理 | 出域前按 40 px 裁边、200 DPI 栅格化 | `app/parse/ocr/crop.py`、`settings.ocr_crop_margin_x/y` |
| 出域留痕 | 每次出域/拦截落 `egress_logs`（仅哈希与字节数，不存正文） | `egress_logs` 19 行（见 2.4） |
| 云通道可关 | `GIPS_EGRESS_ENABLED=false` 即拒绝出域并标 `ocr_failed` | AC-75 演练实测，见 `reports/压测报告.md` 第 4 节 |

### 2.4 出域台账现状（机器可核）

`egress_logs` 共 19 行，按 `(provider, state, dlp_verdict)` 汇总：

| provider | state | dlp_verdict | 行数 | 说明 |
|---|---|---|---|---|
| aliyun | sent | pass | 6 | 2026-11-09 扫描件测试页**已实际出域** |
| aliyun | failed | `provider_error: … ocrServiceNotOpen 401` | 6 | 服务未开通，请求被上游拒绝 |
| tencent | failed | `provider_error: … AuthFailure.SecretIdNot…` | 6 | 凭据为占位符 |
| - | failed | `egress_disabled` | 1 | AC-75 降级演练，未出域 |

读法：出域链路是通的（6 页确实送到阿里云），但**当前云 OCR 不可用**（阿里云服务未开通、腾讯云凭据未配）。
影响是无文本层页面会 `ocr_failed` 转人工复核；有文本层 PDF 不受影响，这也解释了本次 793 块语料为何全程无 OCR。

## 3. 合同条款对应

PRD 第 9 章要求合同包含：零留存、删除时限 ≤ 7 天、不留存训练、模型版本冻结（若用 managed_pinned）、退出时数据导出与销毁。

| 合同条款 | 状态 | 说明 |
|---|---|---|
| 零留存 | **缺项** | 仓库内无与阿里云/腾讯云签订的数据处理协议文本，无法出示 |
| 删除时限 ≤ 7 天 | **缺项** | 同上 |
| 不留存训练 | **缺项** | 同上 |
| 模型版本冻结 | 不适用 | 只用 OCR，不用 managed_pinned 生成档 |
| 退出与销毁 | **缺项** | 同上 |

**为什么不能把这一节写成「已取得口头承诺」**：验收标准自查清单原文是「供应商关闭项有可核对的证据，不是口头承诺」。
没有合同文本，就是没有证据，只能记缺项。

## 4. 与上游规格的口径冲突（需要消解）

执行时发现一处规格内部不一致，照实记录：

| 位置 | 原文 | 冲突 |
|---|---|---|
| `验收标准.md` M5 范围说明 | 「供应商核查照常」；自查清单「供应商关闭项有可核对的证据」 | 要求本期取得供应商侧证据 |
| `契约.md` CT-6 | 「部分：本机供给档与作用域；**云端出域与零留存不执行**」 | 云端出域与零留存不在本期执行 |
| `契约.md` CT-11 | 「部分：出域禁令拦截；**云端调用链路不在本期验收**」 | 云端调用链路不在本期验收 |

上游（契约，依据 PRD 1.2 范围裁定）说「不执行」，下游（验收标准 M5）说「照常」。
按派生链，**本期按上游口径执行**：技术侧证据照交，合同条款不作为本期放行判据。
这条冲突不在这里就地判「通过」，而是作为未闭合项提交收口（第 5 步）消解：
要么在 M5 表里加「云端调用链路不在本期验收」的边界说明（不改判据数值），
要么把 CT-6/CT-11 恢复为全量——两者都需要新开 CHG，不在本次演练里自行决定。
