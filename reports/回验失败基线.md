# 回验失败基线（M2）

- 日期：2026-11-09
- 回验实现：`app/reason/verifier.py`（只读库与原件，不调用生成模型）
- 判据来源：`v1-spec/spec/契约.md` CT-3、`验收标准.md` AC-37 / AC-38 / AC-39 / AC-40

## 1. 回验规则

1. 按 Unicode 码点切片后逐字比较：不做空白归一、不做全半角转换、不做大小写折叠。
2. 页文本路径：`object_store/{doc_id}/v{version_no}/pages/{page_no}.txt`。
3. 跨页引用（`page_end > page_no`）必须给出 `page_spans`，每页独立切片比对。
4. 任一项失败即整链作废，不提供「部分通过」，也不顺手修正 `span_text`。
5. 失败原因枚举：`anchor_missing` / `provision_not_found` / `span_mismatch` /
   `page_mismatch` / `calc_not_allowed`。

## 4. 已知边界

- L 步 payload 里的 `page_no` 是模型自报字段，真实走查中出现过 1（条款实际第 19 页）；
  但 L 步锚点由系统落为 19，回验不受影响。该字段仅作模型过程记录，不参与判定。
- J 步锚点已改为系统按条款规范页码生成（不再采信模型自报页码），真实走查修复后
  落库为第 19 页。
- `provision` 锚点只校验条款存在性，不校验页码是否与条款页码一致；是否把页码
  纳入硬校验需在 M3 与规格方确认。
- 跨页 `page_spans` 的页码必须与页文件一一对应，缺任一页即 `page_mismatch`。
