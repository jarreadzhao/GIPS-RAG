# 模板（直接复制用）

## 1. 统一版本头（四份文件都放，字段名不可改）

```markdown
| 字段 | 内容 |
|---|---|
| 文档 | PRD |
| 版本 | v0.3 |
| 上游文件 | 无 |
| 上游版本 | — |
| 变更单 | CHG-20261104-01 |
| 状态 | 待评审 |
```

派生文件（契约 / 接口 / 验收标准）把「上游文件」填成文件名、「上游版本」填成上游的版本号。
**`spec_link.py` 按字段名解析，改名即失效。**

`状态` 取值固定三种：`草稿` / `待评审` / `已签发`。机检项 [9] 用这个值决定"自查清单有未勾项"是 FAIL 还是 WARN。

---

## 2. 变更单 `changes/CHG-YYYYMMDD-NN.md`

```markdown
# CHG-20261104-01 一句话标题

## 意图
这次要达成什么。只写目的，不写实现方式。

## 上游依据
- PRD 6.11.3：删除 A 模式生成权限
- PRD 附录 E：新增 V7.2 行

## 下游影响（三份逐条回答，无影响也要写理由）
- **契约**：删除 `POST /answer` 的 `mode` 参数 → 第 2 块错误码表去掉 E-4012；
  第 5 块兼容段补"旧客户端调用将收到 400，并行保留 90 天"
- **接口**：`mode` 字段移除，版本 v1.3 → v1.4；旧客户端降级说明
- **验收**：AC-181 / AC-182 重写，新增 AC-196–199；已知不覆盖段增一条

## 不可变更项
本次不许动，动了即视为越界：
- PRD 4.8.2 成本行（已定稿）
- 附录 A 指标阈值

## 验收方式
- `python spec_link.py --root .` 全绿
- `python prd_lint.py spec/PRD.md` 全绿（若装了 PRD 类技能）
```

「下游影响」写成"无需修改"而不给理由的，视为未响应，退回重写。

## 3. pre-commit 钩子

写入 `.git/hooks/pre-commit`，然后 `chmod +x .git/hooks/pre-commit`。

```bash
#!/bin/sh
set -e
python /path/to/spec-propagation/scripts/spec_link.py --root . || {
  echo "四件套联检未通过，禁止提交。"
  echo "确需跳过时用 git commit --no-verify，并在 message 里写明原因。"
  exit 1
}
```

Windows 下 Git Bash 同样有效（`python` 需在 PATH 中；若用 `py`，把命令改成 `py`）。
路径建议写成相对仓库的形式（如 `.spec-tools/spec_link.py`），把脚本随仓库一起提交，换机器不用改。

## 4. commit message

```
spec(CHG-20261104-01): 撤销 R2 检索抽屉

- PRD: 6.11.3 重写、附录 E 增行、4.10.1 补 2 项
- 契约: 删 mode 参数、错误码表去 E-4012、兼容段补 90 天并行
- 接口: v1.4，删 mode 字段
- 验收: AC-181/182 重写，新增 AC-196–199，已知不覆盖 +1

校验: spec_link 全绿 / prd_lint 全绿
```

四份文件**同一个 commit**。一次语义变更 = 一个可回滚单位。

## 5. 残留词表 `spec/stale-terms.json`

被推翻的旧口径放这里，脚本扫描并报警。

```json
{
  "stale_terms": [
    "全私有化",
    "准确率 95%",
    "端到端 2s"
  ]
}
```

**只放真正需要消失的表述。** 如果某词在「取代说明」里必须出现，别放进来，否则每次报警——报警多了就没人看，这一点决定这套检查的存亡。

## 6. 目录骨架

```
<项目>/
├─ spec/
│  ├─ PRD.md
│  ├─ 契约.md
│  ├─ 接口.md
│  ├─ 验收标准.md
│  └─ stale-terms.json
├─ changes/
│  └─ CHG-20261104-01.md
└─ .spec-tools/
   └─ spec_link.py
```

四份文件名不是强制的，脚本支持 `--prd / --contract / --api / --accept` 指定路径。但**四份必须都能被 `spec_link.py` 找到**，否则检查会静默跳过——静默跳过等于没装钩子。

---

## 7. 派生顺序（新项目开场用）

1. `spec/` 放 PRD，跑 `prd_lint.py` 到全绿
2. 从 PRD 派生契约：先只写六块标题，每块填一句"不适用 + 理由"，跑 `spec_link.py` 确认 [8] 通过
3. 逐块替换"不适用"为真实内容，每填一块跑一次
4. 契约定稿后再派生接口（每条 API 挂 `CT-*`），再派生验收（每条 AC 挂 `R-*`）
5. 最后装 pre-commit，**再开第一张 CHG 单走一遍完整链路**

第 5 步的顺序不能反：先装钩子再建文件，会得到一屏 FAIL，然后你就把钩子删了。
