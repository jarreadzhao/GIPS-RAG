## 1. 变更缘由

原来的写法不成立，原因在输入端而不是工期：可获得的原始资料只有 GIPS 2020《Standards for Firms》一份标准原文，判定链的输入端（机构制度文件、firm profile、披露材料与留痕台账）为空。没有机构证据，任何 finding（适用性判定、GAP、四态、签署）都只能凭空生成，而凭空生成的 finding 不构成自查发现，只构成编造。

产品定位经确认收窄为可交付的「GIPS 标准查询与自查工具」：网页端提问 + 中英双语溯源片段，不做合规判定。判定 / 签署 / 盲评 / 漂移监控继续写在执行口径里，会让规格与交付物长期错开——规格说的行为交付物做不到，验收又不敢真跑，判据沦为免责声明。本次按「代码对、规格写宽了」处置：代码一行不动（浅裁），规格把判定链整体标注为「产品范围外·二期候选」，重启需新 CHG 且以真实机构资料为前置。

两个保留执行项按用户拍板不变：R-41 审计哈希链与 AC-48/49/50（同事务写入、触发器禁 UPDATE/DELETE、断链检测）保留——QA 问答链落同一套 `cot_chains` 表；M5 压测口径从「单条款审查 P95 ≤ 90s」改为「问答任务 P95 ≤ 12s」，排队与吞吐口径不变。

## 4. 规格影响判定

> 这次改动会不会让一个本来通过 AC 的实现变成不通过，或让一个本来不通过的行为变成通过？

- 判定与签署类 AC 从「移出本期」改标「产品范围外·二期候选」，判据数值一律未动，重启需新 CHG。不放任何宽。
- AC-45 操作列「发起审查」改「发起问答」：同一拒答行为的 QA 口径表述，判据（不含「通常 / 行业惯例 / 类似标准」）未变，属口径对齐而非放宽。
- AC-71 时延从 90s 收紧到 12s（QA 口径），错误率与并发约束不变。**收紧**。
- 其余 AC 原文保留、编号未删，二期重启时按原文验收仍然成立。
