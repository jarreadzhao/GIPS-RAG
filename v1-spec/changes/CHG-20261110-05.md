## 1. 缺陷 1：中文后置正文误挂 `8.H.4`

**现象**：问「What disclosure is required about the definition of the firm?」，引用 `8.H.4` 返回 103 条中文对照，答案 43,010 字符——整份术语表被当成一条条款的译文。

**根因**：`BACK_MATTER_RE` 只匹配 `GLOSSARY / APPENDIX / ANNEX / INDEX / BIBLIOGRAPHY`，中文译本的「术语表」不识别，`_chunk_provision` 把条款号 `8.H.4` 一路沿用到第 140 页；103 个后置正文块带着错误的 `provision_id` 入库，配对时又被归入 `pr:8.H.4`。

**修复**：
- `BACK_MATTER_RE` 增加中文标题（术语表 / 词汇表 / 附录 / 索引 / 参考书目），并限定「整行只有标题词 + 可选编号」，避免正文里出现「附录…」就误断条款；
- 重新以 `index_mode=display_only` 入库中文译本并重跑配对；
- 新增两个回归用例：中文术语表必须断开条款号；正文提到「附录」不得被当成后置正文。

**修复后**：656 chunk，其中 529 条带条款号、127 条后置正文无条款号；`8.H.4` 引用带 1 条对照，答案 777 字符。

**对应规格**：R-12 / AC-3（`provision_id` 必须对应原件条款层级），D-M2-07（后置正文不得继承条款号）。规格原文已覆盖该行为，属**代码未达标**，不需要改规格。

## 2. 缺陷 2：合规问题被误判为闲聊

**现象**：`What must a firm disclose about fees?` 被判 `chitchat`，不检索、直接回「您好，请提出具体的合规审查问题或条款编号。」

**根因**：`classify_input` 只认条款编号与 `KNOWLEDGE_HINTS` 关键词表；表外问法一律落到 `chitchat`。关键词无法穷举，误判的代价是本可回答的问题被静默吞掉。

**修复**：
- 只有明确问候（`GREETINGS`）或空输入才走 `chitchat`，其余一律按知识问答处理；
- 检索为空时仍走既有明确拒答（AC-80），不会用先验知识补；
- `review_tasks.scope_json` 记录 `intent`，供审计区分「未检索」与「无法回验」；
- 新增断言：无关键词的合规问题必须是 `knowledge`，空输入必须是 `chitchat`。

**修复后**：该问题返回 5 条引用、1,352 字符答案；`你好` 仍不检索（AC-31 不变）。

**对应规格**：R-21 / AC-29 / AC-31。AC-31 只要求「你好」不触发检索，本修复不放宽该条；AC-29 的知识问答要求反而更完整落地。规格原文无需改动。

## 3. 审计口径同步

- AC-79 的 `qa_unverifiable` 只保留「应当有引用却没有」的任务；`intent=chitchat` 的任务单列 `qa_chitchat`，不计分母、不算「无法回验」——按设计就不检索，混进去会把闲聊说成回链失败。
- AC-80 的 `qa_unpersisted` 同样排除 `chitchat`。

**对应规格**：AC-79「未落引用的历史问答记录不得计入分母，须单列」；AC-80 的扫描对象是「问答输出与拒答样本」。口径与原文一致。

## 6. 规格影响判定

> 这次改动会不会让一个本来通过 AC 的实现变成不通过，或让一个本来不通过的行为变成通过？

会——原本被误标条款号的中文块、被误判闲聊的问题，现在按 AC-3 / AC-29 的原文判为不通过。但这是**代码向规格靠拢**，规格没有放宽也没有收紧，因此不改正文、不升版。
