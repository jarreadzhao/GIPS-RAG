## 1. 变更缘由

PRD 1.3 的召回率口径写的是「用条款编号 / 标题 / 义务原文首句反查自身条款」，验收 M1 进入条件与 AC-82 同样要求按「编号 / 标题 / 义务首句」生成查询集。

实测发现这条写法不成立：GIPS 2020《Standards for Firms》的条款以 `1.A.4` 这类编号组织，**没有独立标题**。`条款证据清单.csv` 里唯一能当标题用的是章名，而全库只有 8 个章，拿章名查询时 gold 只能是整章 20～85 条，Recall@5 会退化成章级命中，与条款级指标不是同一粒度，不能放进同一个分母。

这属于规格**写错**：它假设了一个原件里不存在的字段。按「规格是承诺，代码是事实」的处置，回写 PRD 并沿派生链改到验收，而不是让报告长期挂一条「口径偏离」。

## 2. 处置

| 层 | 改动 |
|---|---|
| PRD | 1.3 召回率口径改为「用条款编号 / 义务原文首句反查自身条款」，并写明「GIPS 条款无独立标题，标题变体不可用，不得用章名替代」 |
| 契约 | 仅版本头前进至 v1.9，正文无改动（契约没有评测集构造条款） |
| 接口 | 仅版本头前进至 v1.9，正文无改动 |
| 验收 | AC-82 操作列改为「每条条款的编号 / 义务首句；GIPS 条款无独立标题，不生成标题变体」；M1 进入条件的评测集构造同步去掉「标题」并注明原因 |

**未降低标准**：Recall@5 阈值仍为 0.92，两次差值仍为 ≤1 个百分点，查询集总量仍为 200 条（golden 155 / dev 45），已测数字一个未改。删掉的变体从未被生成过——即使不删，它贡献的也是 0 条查询，不会让任何一次实测更容易通过。章名查询继续作为补充观测单列，不进入 AC-82 分母。

## 3. 规格判定

按「这次改动会不会让一个本来通过 AC 的实现变成不通过，或让不通过的行为变成通过」：

- **不会改变任何一次实测的判定结果**：修改前 `自生成口径评测.md` 已按两种变体跑出 R@5 = 1.0000，修改后仍是同一批查询、同一批数字。
- 但**会改变规格本身的真值**：原写法要求的第三种变体在原件中不存在，属于规格错误，因此必须升版并开单，不能只在报告里注一句「口径偏离」长期挂着。

## 4. 下游影响

- **契约**：无正文改动，仅版本头。CT-1～CT-11 的召回 / 评测相关表述不涉及查询集构造。
- **接口**：无正文改动，仅版本头。`POST /retrieval/test` 不定义查询集构成。
- **验收**：AC-82 操作列与 M1 进入条件的评测集行改动；判定阈值、条数、分母规则均未动。
- **报告**：`reports/自生成口径评测.md` 第 1 节把「需要另开变更单」改为「已由本单修订」；`GAP-M1-02` 关闭。

## 5. 遗留

- 章名查询仍是补充观测，未纳入任何 AC；若要把它做成正式指标，需另立 AC。
- 本次只修「标题」变体，未触碰 200 条总量与 golden / dev 拆分规则。
