| 项 | 内容 |
|---|---|
| 变更单号 | CHG-20261110-17 |
| 日期 | 2026-11-10 |
| 类型 | 需求新增（问答语种）+ 接口新增字段 + 前端新增 |
| 发起 | 用户提出「回答首先返回中文，不要英文；前端加一个英文版，选择英文版时全部回答用英文，返回的文档片段也只留英文」 |
| 影响文件 | 后端 `app/reason/orchestrator.py`、`app/api/reviews.py`；前端 `frontend/js/i18n.js`（新增）、`frontend/js/pages/chat.js`、`frontend/js/api.js`、`frontend/js/main.js`、`frontend/js/app.js`、`frontend/js/pages/search.js`、`frontend/js/pages/docs.js`、`frontend/index.html`、`frontend/css/style.css`；测试 `tests/test_m2_review.py`、`tests/test_scenario_matrix.py` |

## 1. 变更缘由

原实现是「英文原文 + 中文对照」的双语引用：检索只命中英文块，答案模板固定为英文原文，`citations[].translations[]` 再附带中文译文。这产生两个问题：

1. **中文模式下答案混排两种语言**。用户默认要中文，但答案首段是英文原文，中文只是附注；命中条款缺译文时 `translations=[]`，中文读者实际拿不到中文。
2. **没有英文版**。界面文案、模板、拒答话术全是中文，海外或英文评审场景无法使用。

规格原文对此没有规定，属于「规格写漏」（代码做了双语对照、规格没写语种语义），不是「代码没做到规格要求」。因此按派生链从 PRD 补一条 R，再逐层追认。

## 2. 规格变更（PRD → 契约 → 接口 → 验收）

| 文件 | 改动 | 类型 |
|---|---|---|
| `spec/PRD.md` | 新增 **R-49**：答案语种由 `answer_lang` 单一决定；同一回答不混排；锚点指向被展示语种一侧；中文缺译文时明确告知「无中文译文、可切换英文版」，不得说「未检索到」 | 补漏 |
| `spec/契约.md` | CT-2 请求表新增 `answer_lang` 行；CT-2 硬规则新增第 7 条（语种单一、锚点对侧、`translations[]` 恒空、`zh_unavailable`、进入幂等指纹） | 追认 |
| `spec/接口.md` | API-4 新增 `answer_lang` 参数（默认 zh，非法值 400 `VALIDATION_FAILED`）；重写响应语种规则；`citations[].translations[]` 注明本期恒空；新增 `warnings[]` 说明；API-5 补「语种取落库时的 `answer_lang`」 | 追认 |
| `spec/验收标准.md` | 新增 **AC-83**（来源 R-49）；AC-5 末句由「中文对照逐条回验」改为「同一 `pair_id` 两侧原文各自回验」；AC-79 / AC-80 注明 `translations[]` 本期恒空；适用范围 82 → 83 条 | 追认 |

四份版本头：PRD `v1.10`；契约 / 接口 / 验收 `版本 v1.10` / `上游版本 v1.10` / `变更单 CHG-20261110-17`。

**没有降低任何阈值**：AC-79 的可回链率仍是 100%，AC-80 的越界扫描范围不变，AC-5 的配对规则（等量 1:1、不等量整条共用、`display_only` 不入索引）一字未动。只是把「回验对象」从「引用 + 中文对照」改为「当前语种那一侧引用」——对照条目已不再产生，若保留原表述会变成永远无法满足的空断言。

## 3. 代码处置

### 3.1 后端

| 文件 | 改动 |
|---|---|
| `app/reason/orchestrator.py` | `ReviewRequest` 新增 `answer_lang`；`_run_qa` 按语种收集引用与选模板；`_collect_citations(hits, lang)` / `_citation_for_chunk(..., lang)` 在 zh 模式按 `pair_id` 反查中文块并回验，查不到则丢弃并记 `zh_unavailable:<provision_id>`；`translations` 恒 `[]`；删除 `_translations_for()`；`_extractive_answer` / `_refusal` 按语种分支；`_persist_qa_citations` 落 `answer_lang`；`_replay_qa` 从 payload 读语种；`_fingerprint` 纳入 `answer_lang` |
| `app/api/reviews.py` | `ReviewBody` 新增 `answer_lang`；端点内校验非法值并抛 `AppError("VALIDATION_FAILED")`，返回 400 而非裸 422 |

中文模式命中条款无中文译文时返回专用话术，并在 `warnings[]` 记 `zh_unavailable:<provision_id>`；不表述为「未检索到」，因为检索确实命中了，缺的是译文。

### 3.2 前端

| 文件 | 改动 |
|---|---|
| `frontend/js/i18n.js`（新增） | 中英界面词典与语言状态；`setLang` 写 `localStorage` 后整页重载（会话历史在 `sessionStorage` 不丢） |
| `frontend/js/pages/chat.js` | 新增语种切换条；问答请求带 `lang`；引用卡片按单语种渲染（zh 显示中文块、en 显示英文块，不再拼 `translations`）；修复 `$$` 未导入与轮询读错状态字段 |
| `frontend/js/api.js` | `askQA` 透传 `answer_lang` |
| `frontend/js/main.js`、`app.js`、`pages/search.js`、`pages/docs.js`、`index.html` | 导航、按钮、提示、健康状态、文档标签全部走 `t()` |
| `frontend/css/style.css` | 新增 `.chat-langbar` / `.lang-btn` 样式 |

### 3.3 测试

`tests/test_m2_review.py`、`tests/test_scenario_matrix.py` 按新契约改编：原「引用携带中文对照」用例改为「zh 模式只引中文块」，新增「en 模式只回英文」用例；落库回放用例显式传 `answer_lang="en"`。判据未放宽，均为针对性替换。

两文件实测 **102 条用例 / 0 失败 / 36 跳过**（跳过项为环境依赖，非本单引入）。

## 4. 下游影响

- **契约（CT-2）**：已改。新增 `answer_lang` 请求字段与第 7 条硬规则；`translations[]` 语义从「中文对照」改为「本期恒空、仅兼容历史回放」。
- **接口（API-4 / API-5）**：已改。新增参数与语种规则、`warnings[]`，非法值 400；API-5 回放语种取落库值。响应形状未删字段，仅语义收窄，属兼容变更。
- **验收（AC-5 / AC-79 / AC-80 / AC-83）**：已改。新增 AC-83 覆盖语种不混排、`doc_id` 对侧、非法值 400、同键改语种 409；原三条按新口径同步表述，阈值不变。
- **codemap**：`app/reason/orchestrator.py`、`app/api/reviews.py` 两行补 R-49；新增「前端」节，登记 `frontend/js/i18n.js`、`frontend/js/pages/chat.js`、`frontend/js/api.js`。

## 6. 已知不覆盖

| 项 | 原因 |
|---|---|
| 中文模式下缺译文条款的端到端体验 | 当前仅有测试构造的 `zh_unavailable` 分支；真实库中文块 529/656，缺口条款未逐条走查前端的提示是否可读 |
| 历史问答记录回放 | 旧记录 payload 无 `answer_lang`，按旧双语口径回放；未做批量回填（要重跑检索才能补语种，成本高于价值） |
| 前端词典完整性 | `t()` 覆盖工作台主要文案，未做「键缺失」的构建期检查；新增页面需手工补词条 |
| 英文模式下的中文查询 | 检索侧未按语种过滤查询语言，英文模式仍可能命中中文块（`pair_id` 反查方向不同），当前未纳入 AC-83 |
