## 1. 变更缘由

`_run_qa` 原来把命中的 `provision_id` 用「；」拼成字符串当答案：

- 没有页码、字符区间与 `span_hash`，问答链路无法按 AC-79 回验；
- 答案不落库，AC-80 对问答输出没有可扫描对象，只能记 N/A；
- 检索为空时返回空字符串，不构成 AC-80 要求的「明确拒答」。

用户已把产品定位收敛为查询型工具：能提问、能回答、能溯源到原文片段。问答输出必须从
「条款编号列表」改成「抽句式答案 + 结构化引用列表」。

## 2. 处置

### 2.1 代码

| 文件 | 改动 |
|---|---|
| `app/reason/verifier.py` | 新增 `verify_ref()`：单条引用按 CT-3 同一口径回验（只读原件、码点切片、字节比较） |
| `app/reason/orchestrator.py` | `_run_qa` 逐条款取块、回库读定位字段、`verify_ref` 通过后才进答案；答案改为抽句式；按 `E` 步写 `cot_chains`（`task_id` 非空、`finding_id` 为空）；空检索写 `answer_mode=refusal`；`_replay` 从链重建答案，不重新检索 |
| `app/api/reviews.py` | `GET /reviews/{task_id}` 对 qa 任务补 `citations[]`，取自 E 步 `anchors_json` |
| `tests/test_m2_review.py` | 新增结构化引用、落库、幂等回放、空检索拒答四条断言 |
| `scripts/ac79_ac80_audit.py` | AC-79 把 QA 引用计入总体并逐条独立回验；AC-80 扫 QA 答案模板（先扣除引文）；单列「未落引用的历史问答」 |

答案结构（`_extractive_answer`）：

```
以下为检索命中的条款原文，未做改写：

1.A.5：<原件逐字片段>
```

除固定模板与 `provision_id` 外，答案正文全部是已回验的原件引文，没有模型生成文本。

### 2.2 实测

- 语料：`gips2020`（English，146 页），Milvus `gips_chunks` 793 条；
- 回放：6 个真实问题各两次，共 12 条 qa 任务；另 1 条空检索拒答；
- 结果：

```
AC-79 证据锚点 54/54 可回链，可回链率 100.00%（正式审查 0，QA 引用 54；无引用不可回验的旧 QA 任务 12 条）
AC-80 QA 答案 13 段：实数命中 0，禁用语命中 0，明确拒答 1 条，答案未落库无法核验 12 条
```

## 3. 下游影响（三份逐条回答）

| 文档 | 是否受影响 | 理由 |
|---|---|---|
| PRD | 否（仅换版本号与单号） | R-28 / R-29 / R-34 / R-35 已要求「没有答案要分类输出」「每个结论挂锚点」「规则引擎回验」；本次是把 QA 补到这些既有要求上，未新增或改写 R |
| 契约 | **是** | CT-3 补硬规则 5 / 6：QA 引用按单条引用走同一回验口径；`span_text` 只进 `anchors_json`，`payload_json` 不存条款原文 |
| 接口 | **是** | API-4 补 qa 响应的 `answer` / `citations[]` / `intent` 与空检索语义；API-5 对 qa 补 `citations[]` |
| 验收标准 | **是** | AC-79 删掉「本期未产生任何带锚点的问答记录」这一已失真的现状描述，保留 100% 与零分母规则，并补「未落引用的历史记录须单列、不得省略」；AC-80 的操作对象从「抽查」改为「全部问答输出」，并写明抽句式答案的扫描边界 |

## 4. 规格影响判定

> 这次改动会不会让一个本来通过 AC 的实现变成不通过，或让一个本来不通过的行为变成通过？

- AC-79：改动前旧实现没有引用，记 N/A；改动后新问答 54 条全部回链，仍按 100% 判。**未降低标准**，且新增「历史记录不得省略」防止用分母裁剪刷出 100%。
- AC-80：改动前问答无可扫描对象；改动后 13 段全部扫描。扣除引文再扫模板，是把「原件里的数字」与「模型写的数字」分开，不是给答案开豁免——引文仍要过 AC-79 的逐字回验。
- AC-79 删掉的那句是**现状描述**而非判据，现状已变化（产生了 13 条带答案的 qa 记录），保留原句会让规格与台账不符。

## 7. 回滚方式

回退 `app/reason/orchestrator.py` 的 `_run_qa` / `_replay` 与新落库的 E 步即可恢复旧行为；
已写入的 `cot_chains` 不会因回滚删除（append-only），但旧代码不读它们。
回滚后 AC-79 会退回「总体为 0 / N/A」，AC-80 的问答段退回 N/A。
