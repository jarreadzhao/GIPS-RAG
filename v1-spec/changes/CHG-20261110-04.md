## 1. 变更缘由

上一版 R-13 写的是「一个双语 chunk 同时含英文原文与中文译文，`pair_id` 是主键的一部分」。实现时发现这条写不成可回验的形态：

`chunks` 每条记录只有一套 `page_no / char_start / char_end`。一个同时装中英的块，字符区间只能对应**一份**原件；另一侧的片段无法定位到它自己的页码与码点区间，`span_hash` 也就无从复算。R-30 / R-34 要求引用必须由规则引擎做字节级回验，两条放在一起自相矛盾。

实测还暴露一个次生问题：语种按前 20 个清洗块判定，中文译版封面与页眉是英文，整份 140 页文档被判成 `mixed`，配对脚本按 `lang='zh'` 找不到任何目标块。

## 2. 处置

### 2.1 规格回写（PRD → 契约 → 接口 → 验收）

| 文档 | 改动 |
|---|---|
| PRD | R-13 改为「英文块唯一进入索引，中文侧作为 `display_only` 显示层按 `pair_id` 关联，不单独建索引、不参与召回；中文对照同样逐条回验」；4.5 第 1 条改写并补三条配对规则；10.1 `documents` 补 `index_status` 含 `display_only`；10.3 注明 Milvus 的 `pair_id` 在配对后可能为空，检索与回验以 SQLite 为准 |
| 契约 | CT-4 补「显示层构建」表：只落 SQLite、`milvus_count=0` 不适用计数相等、检索双重排除、前置校验不放宽、责任划分；CT-4 末尾补双语配对的可重入后置语义；CT-9 索引联动注明 `display_only` 走显示层构建 |
| 接口 | API-4 的 `citations[]` 增加 `translations[]` 及其字段，注明逐条回验、答案追加 `中文：` 行；API-5 注明回放从落库锚点重建；API-18 增加 `index_mode` 与对应响应字段 |
| 验收标准 | AC-5 按双行配对重写，判据含 `milvus_count=0`、检索不可见、`pair_id` 组内唯一、中文对照逐条回验；AC-79 把中文对照计入同一分母；AC-80 的扣除范围加入 `translations[].span_text` |

**为什么原来的写法不成立**：不是实现偷懒，而是原句把「pair 为原子」误解成「两条原件挤进一条记录」。主键可以共享（`pair_id`），字符区间不能共享。规格写错，按合法回写处理。

### 2.3 实测

- 原件：`standard_paper/Chinese-Translation-2020-Firms.pdf`，140 页，文本层覆盖 93.57%，未调 OCR；
- 入库：`index_mode=display_only`，655 chunk，`milvus_count=0`，质量闸门通过；
- 配对：英文 562 个带条款号的块中 561 个配对（99.82%），中文 631 个全部配对；449 个条款按块 1:1，51 个条款按整条配对（涉及 112 个英文块）；英文独有 `7.C.32`；
- 回放：1 个真实问题，5 条引用、7 条中文对照；同 `Idempotency-Key` 重发 `replayed=true`，结果一致；
- 审计：

      （正式审查 0，QA 引用 59，其中中文对照 7；无引用不可回验的旧 QA 任务 12 条）

- 全量测试 106 条通过。

## 3. 下游影响（三份逐条回答）

| 文档 | 是否受影响 | 理由 |
|---|---|---|
| PRD | **是** | R-13 与 4.5 的原子单位定义必须改：原句要求单 chunk 同含中英，与单套字符区间不可兼容；10.1 / 10.3 补 `display_only` 与 `pair_id` 的真实存放位置 |
| 契约 | **是** | CT-4 增加显示层构建路径与计数规则例外；CT-9 发布联动的分支；CT-4 补配对的后置可重入语义与责任划分 |
| 接口 | **是** | API-18 增加 `index_mode` 与响应字段；API-4 / API-5 的 qa 引用增加 `translations[]` 并明确逐条回验 |
| 验收标准 | **是** | AC-5 按可验证的双行设计重写；AC-79 分母纳入中文对照；AC-80 扣除范围纳入中文对照。三条都只收紧、不放宽 |

## 4. 规格影响判定

> 这次改动会不会让一个本来通过 AC 的实现变成不通过，或让一个本来不通过的行为变成通过？

- AC-5：原判据「每个 chunk 同时含中英文本」在单套字符区间下无法同时满足回验，属于**写错**而非写宽。改写后判据更具体：`milvus_count=0`、检索不可见、组内唯一、中文逐条回验。按新口径，只把中文写进 SQLite 却没有 `pair_id`、或中文对照未回验的实现仍然不通过。
- AC-79：分母扩大（中文对照计入），通过门槛仍是 100%。**收紧**。
- AC-80：扣除范围扩大，模板措辞更少可藏数字的地方。**收紧**。

## 7. 回滚方式

回退本单代码即可：中文块留在 SQLite 但不再被引用读取（`pair_id` 反查代码移除后 `translations` 恒为 `[]`）；`display_only` 文档不会被检索命中，回滚无检索侧风险。schema 的 `display_only` 枚举值可保留（多一个合法值不影响旧代码写入）。已写入的 `cot_chains` 不删除，旧代码忽略 `translations` 字段。
