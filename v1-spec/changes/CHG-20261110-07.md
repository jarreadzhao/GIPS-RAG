## 1. 变更缘由

CHG-20261110-06 已把产品定位收窄为「GIPS 标准查询与自查工具」，验收口径为 Q0 四条（AC-79/80/81/82）+ M0/M1/M2 保留段 + M3/M4/M5 保留段。后端三条接口（检索 `/provisions/search`、问答 `/reviews task_type=qa`、文档状态 `/documents/{doc_id}`）在收窄范围内均已实现且实测可用。

此时前端仍是空白——用户无法通过浏览器触达后端能力，CHG-06 收窄后的交付口径与实际可见物之间有一段空挡。第 1 步即填这段空挡。

## 2. 处置

### 2.1 代码

| 文件 | 改动 |
|---|---|
| `app/main.py` | 加 `from fastapi.middleware.cors import CORSMiddleware`；在 `create_app()` 里、路由注册前加 `CORSMiddleware(allow_origins=["*"], allow_headers=["*"], allow_methods=["*"], allow_credentials=False)`——解决单机联调跨域（前端 `:8765` 对后端 `:8011`）。规格未定义跨域策略，此项为实现细节，不影响任何 R/CT/AC |
| `frontend/index.html` | 操作台外壳：左导航（问答/检索/文档三入口 + 暂未开放的评测入口）+ 顶部 appbar（breadcrumb + 后端健康灯）+ 主区 + Toast 容器。零依赖，单入口 ES module |
| `frontend/js/api.js` | fetch 封装：API_BASE 默认 `http://127.0.0.1:8011`；所有请求自动注入 `X-Role: reviewer` / `X-Dept: compliance` / `Idempotency-Key`（单机前端无网关，靠 Role/Dept 头让后端 `resolve_acl_scope()` 按角色映射生成 acl_scope）；提供 `healthz()` / `searchProvisions()` / `askQA()` / `getReview()` / `getDocument()` 五个方法 |
| `frontend/js/app.js` | 基座：hash 路由（`#/chat` / `#/search` / `#/docs`）、导航渲染、Toast、`$$`/`$`/`esc`/`sleep` DOM 工具、后端健康轮询 |
| `frontend/js/main.js` | 入口：组装 NAV + 路由表，调用 `startApp()` |
| `frontend/js/pages/chat.js` | 问答工作台：左侧会话历史（sessionStorage 持久化，最多 30 条）+ 右侧输入框 + 发送按钮。POST `/reviews task_type=qa` → 轮询 GET `/reviews/{task_id}` → 渲染答案 + citations（含中英双语对照 `translations[]`）。Ctrl+Enter 发送 |
| `frontend/js/pages/search.js` | 条款检索工作台：搜索框 + Top-5 重排条款卡片（provision_id / type / 命中通道标签 / RRF 分 / 候选 chunk 展开）+ 原始候选表格（通道/provision_id/score/page/text 前 260 字）。后端 `/provisions/search` 三通道全开，top_k=20 |
| `frontend/js/pages/docs.js` | 文档管理：展示 SQLite `documents` 表中 `gips2020`（英文原文 146 页）与 `gips2020-zh`（中文译版 140 页，`index_status=display_only`）两张，从后端 `/documents/{doc_id}` 刷新 version_no/status/index_status/parser/page_count/text_layer_ratio/active_version |
| `frontend/css/style.css` | 设计令牌：改自参考项目 finance_project，主色靛蓝-青蓝（#2563EB），去掉 A 股语义红涨绿跌；组件样式（外壳/导航/appbar/Panel/Chip/Table/Toast/问答气泡/引用卡片/滚动条） |

### 2.2 实测

- 后端：`/healthz` → `ok, version 0.1.0-M2`，CORS 预检 OPTIONS → `200 OK + Access-Control-Allow-Origin: *`
- 检索：shell 调 `/provisions/search?q=1.A.4&channels=dense,sparse,sql` → 41 candidates / Top-5 / 1.A.4 排第 2
- 前端静态服务：`python -m http.server 8765` 在 `frontend/` 目录下运行
- 浏览器三步 PASS：①首页加载 + 健康灯在线；②检索 1.A.4 → Top-5 + 41 行候选；③问答工作台空状态 + 输入框/发送按钮；④文档管理两卡片刷新后正常显示 version/status/index_status/pages/text_layer
- console 全程无报错

### 2.3 为什么规格没动

CHG-20261110-06 刚把交付口径收窄为「标准查询与自查工具」，规格 v1.7 已明确 QA 链路保留（AC-79/80/81/82、CT-1、R-34）。本次前端是该收窄口径的**实现**，不是**改动**——规格条目里没有"前端用什么技术栈、入口是什么"这类实现细节，因此规格正文无需修订。

CORS middleware 同理：规格未定义"允许哪些跨域"或"禁止跨域"，此项为实现层配置，不触发回写。
