# CHG-20261110-16 双语配对键丢失的启动自检

| 项 | 内容 |
|---|---|
| 变更单号 | CHG-20261110-16 |
| 日期 | 2026-11-10 |
| 类型 | 代码新增（可观测性） |
| 发起 | 用户提问「为什么回答没有返回中文片段」，查明为英文侧 `pair_id` 被重入库冲掉，且该状态**静默无告警** |
| 影响文件 | `app/index/pairing.py`、`app/main.py` |
| 版本结果 | 规格四份**不动**（仍 v1.9 / 上游 v1.9 / CHG-20261110-12） |

## 1. 变更缘由

中英对照的取用链路是：检索命中**英文**块 → 读该块的 `chunks.pair_id` → 按 `pair_id` 取中文显示层块（`app/reason/orchestrator.py`）。因此 `pair_id` 只写在中文侧是无效的，必须两侧都有。

实测 2026-11-10 的库状态：

| 侧 | 块数 | 有 pair_id |
|---|---|---|
| `gips2020`（en） | 793 | **0** |
| `gips2020-zh`（zh） | 656 | 529 |

英文侧全空，所以 `translations` 恒为 `[]`，`warnings` 也为空——不是回验失败被过滤，而是 `_translations_for()` 从未被调用。

根因在 `IndexBuilder._stage_one()`：它先 `DELETE` 再按解析结果 `INSERT`，而单语 PDF 解析出来的 `pair_id` 是 `None`。**英文文档每重入库一次，配对键就被整体清空一次**，必须重跑 `scripts/pair_bilingual.py` 才恢复。配对本身是独立脚本（R-13 / AC-5 的既定分工），这个耦合没有写进任何地方，失效时也不留痕迹。

本次只补「能看见」，不改配对规则、不改取用链路。

## 2. 处置

| 文件 | 改动 |
|---|---|
| `app/index/pairing.py` | 新增 `pairing_status(db)`：只读 SQLite，统计 en/zh 两侧 active 块数与其中有 `pair_id` 的块数；空库各项为 0，调用方不必特判 |
| `app/main.py` | 新增 `_check_bilingual_pairing(db)`，在 `build_context()` 里紧随 `recover_incomplete()` 调用：**中文侧有配对键、英文侧却全空**时打一条 `WARNING bilingual_pairing_lost`，附带两侧计数与恢复命令 |

告警而不阻断启动：配对键只决定引用里带不带中文对照，不影响检索、答案与任何 AC 的判定，不该因为展示层缺失让服务起不来。也不自动修复——自动重配对会把「什么时候丢的、丢了几次」这件事一起抹掉。

## 3. 规格判定

按「这次改动会不会让一个本来通过 AC 的实现变成不通过，或让不通过的行为变成通过」：

- **不会**。R-13 的配对规则（等量 1:1、不等量整条共用、无条款不配对）一字未改；AC-5 判定的是配对结果本身，自检不产生也不修改任何配对结果。
- 新增的是日志：把原本静默的数据状态缺陷变成可观测告警。判据阈值、条目文字均未动。
- 因此四份规格不动，本单为纯代码新增。

## 4. 下游影响

- **契约**：无影响。CT-4 的入库契约未涉及启动自检。
- **接口**：无影响。未新增路由，`/healthz` 响应未改。
- **验收**：无影响。AC-5 / AC-79 的判定仍以库内记录为准。
- **codemap**：`app/index/pairing.py` 已有条目（R-13, AC-5），`app/main.py` 已有条目（R-1, R-6），不新增行。

## 5. 验证

以真实库与一份「英文侧 pair_id 被清空」的副本各跑一次 `_check_bilingual_pairing()`：

```
正常库:   {'en_total': 797, 'en_paired': 561, 'zh_total': 656, 'zh_paired': 529}  → 无输出
模拟丢失: {'en_total': 797, 'en_paired': 0,   'zh_total': 656, 'zh_paired': 529}
  {"level": "WARNING", "event": "bilingual_pairing_lost", "en_total": 797,
   "en_paired": 0, "zh_paired": 529, "hint": "英文侧 pair_id 全空，引用不会带中文对照；重跑 scripts/pair_bilingual.py 可恢复"}
```

恢复动作不在本单：英文侧丢失已用 `scripts/pair_bilingual.py` 对真实库恢复（561/562 英文块、529/529 中文块），本单只负责让同类失效在下次启动时能被看见。

## 6. 已知不覆盖

| 项 | 原因 |
|---|---|
| 部分丢失（如英文侧只剩少量块有 pair_id） | 本单只在「英文侧全空」时告警，比例型阈值需要先定判据，留待确认 |
| 中文侧丢失（英文侧正常） | 对称情形，当前中文译版是单文档显示层，优先级低，未加检查 |
| 自动重跑配对 | 有意不做：自动修复会掩盖失效频次 |
