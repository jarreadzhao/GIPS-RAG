# CHG-20261110-15 问答工作台发送无响应修复

| 项 | 内容 |
|---|---|
| 变更单号 | CHG-20261110-15 |
| 日期 | 2026-11-10 |
| 类型 | 代码修正（前端联调缺陷） |
| 发起 | 用户在 `frontend/` 问答工作台点「发送」后主区域始终空白，无任何提示 |
| 影响文件 | `frontend/js/pages/chat.js` |
| 版本结果 | 规格四份**不动**（仍 v1.9 / 上游 v1.9 / CHG-20261110-12） |

## 1. 变更缘由

用户截图显示：会话历史里已出现该条会话（标题即提问内容、标注「1 条」），但主区域空白、输入框文本未清空、按钮仍为「发送」。三处现象合并指向同一个事实——`handleSend()` 在发请求**之前**就抛了异常。

复现与定位：

1. `chat.js` 顶部只 `import { $, esc, toast, sleep }`，**漏了 `$$`**；`renderHistory()` 第 50 行用 `$$("#historyList .chat-history-item")` 绑点击事件。
2. `handleSend()` 顺序是「push 用户消息 → saveHistory → renderAll() → 置按钮忙态 → askQA」。`renderAll()` 在 `$$` 处抛 `ReferenceError`，函数中断，`askQA` 从未执行。
3. 数据库侧佐证：`review_tasks` 最近记录中**没有** 21:10:49 那条提问，只有我 21:12:13 手工补测的一条。即请求确实没发出，不是后端慢或拒答。
4. 初始页面加载不崩，因为历史为空时 `renderHistory()` 在 `$$` 之前就 `return` 了——所以「打开正常、一发送就死」。

同一函数里还有第二处缺陷，即使 `$$` 修好也会表现为「转 8 秒圈后显示『后端未返回 answer』」：

- `POST /reviews` 对 qa 任务**同步返回终态**，`status` / `answer` / `citations` 都在**顶层**（实测 HTTP 202，`status: "succeeded"`，`answer` 为抽句式条款原文，`citations` 两条带 `span_hash`）。
- `GET /reviews/{task_id}` 的结构是 `{ task, findings, steps, queue_position, citations }`——状态在 **`task.status`** 下，答案根本不在该响应里。
- 原代码读 `data.status` 与 `data.findings.answer`，两条路径都取不到值，轮询永远等不到终态。

## 2. 处置

| 位置 | 改动 |
|---|---|
| 导入 | 补 `$$`（`app.js` 已导出，仅未引入） |
| 常量 | 新增 `TERMINAL = new Set(["succeeded", "failed"])` |
| 取数 | 直接采用 `POST /reviews` 的同步返回；仅当 `status` 非终态时才轮询 `GET /reviews/{task_id}`，且按 `task.status` 读状态 |
| 组答 | `answer` 取顶层 `data.answer`；`citations` 取顶层 `data.citations`（qa 的 E 步锚点由后端单独列出）；`verdict` 取 `findings[0].verdict`（qa 无 finding 时为 undefined） |
| 兜底 | 无 `answer` 时展示「任务 X 状态 Y，未返回答案」，不再静默空白 |

未改后端、未改 API 契约、未改任何阈值。

## 3. 规格判定

按「这次改动会不会让一个本来通过 AC 的实现变成不通过，或让不通过的行为变成通过」：

- **不会**。`POST /reviews` 与 `GET /reviews/{task_id}` 的响应结构本来就是 API-4 / API-5 定义的样子，本次是前端**改回按契约读**，不是契约迁就前端。
- AC-79 / AC-80 的判据作用在**落库的引用与答案**上，由 `scripts/ac79_ac80_audit.py` 直接读库核验，与前端渲染无关；前端此前渲染不出内容，不改变任何 AC 的得失。
- 因此四份规格不动，本单为纯前端缺陷修正。

## 4. 下游影响

- **契约**：无影响。CT-1 / CT-2 / CT-3 未改。
- **接口**：无影响。API-4 / API-5 的路由、请求体、响应结构一字未动。
- **验收**：无影响。AC-79 / AC-80 仍以库内记录为准。
- **codemap**：`frontend/` 未挂 R / AC 编号（沿用 CHG-20261110-07 的处置），不加映射行。

2. 气泡内含条款 `3.A.5` 原文，并渲染出带 `provision_id` 与 `hash` 的引用卡片；
3. console 无 `Uncaught ReferenceError`。
