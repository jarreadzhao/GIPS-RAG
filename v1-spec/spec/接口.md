## 第 1 章 通用约定

### 1.1 认证与上下文

| 项 | 约定 |
|---|---|
| 认证 | `Authorization: Bearer <access_token>`，RS256，有效期 30 分钟 |
| 刷新 | `refresh_token` 有效期 8 小时，单次使用后轮换 |
| 角色 | 由令牌 `role` 声明承载，服务端不读请求体或文本中的角色声明 |
| 上下文注入 | 网关解析令牌后向下游注入 `actor_id`、`role`、`acl_scope`、`request_id` |
| 追踪 | 响应头返回 `X-Request-Id`，与日志和 Langfuse trace 同值 |

### 1.2 请求与响应格式

- 请求与响应均为 `application/json; charset=utf-8`，文件上传除外。
- 时间一律 RFC 3339 UTC 毫秒，如 `2026-11-07T03:12:44.120Z`。
- 金额与比率用字符串定点数，如 `"0.0842"`，不用浮点。
- 列表分页用游标：`cursor` 与 `limit`（默认 20，上限 100），响应含 `next_cursor`。**不用 offset 分页**，台账会持续追加，offset 会漏行。

### 1.3 错误结构

```json
{
  "code": "PROFILE_MISSING",
  "message": "formal 任务需要 firm profile 快照",
  "retryable": false,
  "request_id": "01JC3W8Z9K4Q2M6T7R5V1B0X3N",
  "details": { "missing": ["has_pooled_fund", "compliance_start_year"] }
}
```

错误码全集见《契约》2.2。客户端必须以 `code` 判定，不得解析 `message`。

### 1.4 幂等

| 接口 | 幂等键 | 有效期 |
|---|---|---|
| `POST /reviews` | `Idempotency-Key` 头，客户端生成 ULID | 24 小时 |
| `POST /documents` | 服务端用文件哈希，无需客户端传 | 永久（按哈希） |
| `POST /documents/{id}/publish` | `confirm_token` + `version_no` | 5 分钟 |
| `POST /findings/{id}/signoff` | `row_version` 作乐观锁 | 请求级 |
| `POST /eval/run` | `config_hash` | 1 小时 |

同一幂等键不同载荷 → `409 IDEMPOTENCY_CONFLICT`。

### 1.5 流式响应

`GET /reviews/{id}/stream` 使用 SSE，事件类型四种：

| event | data | 说明 |
|---|---|---|
| `step` | `step_no`、`type`、`summary` | 每完成一步推一次 |
| `finding` | 完整 finding 草稿 | 判定完成时推一次 |
| `error` | `code`、`message` | 出错即终止，不再推后续事件 |
| `done` | `task_id`、`status` | 终态 |

SSE 断线重连用 `Last-Event-ID`，服务端从该序号后续推，**不重放已推的 step**。

## 第 3 章 接口定义

### 3.1 认证与用户

#### API-1 POST /auth/login （CT-8）

用户名密码登录，写审计。

请求：`username`（必填）、`password`（必填）、`mfa_code`（条件必填，已绑定 MFA 时）。

响应 200：`access_token`、`refresh_token`、`expires_in`、`role`、`acl_scope`。

错误：`AUTH_INVALID` 401（凭据错，统一文案，不区分用户是否存在）、`MFA_REQUIRED` 401、`UPSTREAM_RATE_LIMITED` 429（连续失败 5 次锁 15 分钟）。

审计：无论成败都写 `audit_logs`，只记 `username` 与结果，不记密码。

#### API-2 POST /auth/refresh （CT-8）

轮换刷新令牌。

请求：`refresh_token`。响应 200：新的 `access_token` 与 `refresh_token`。

错误：`AUTH_INVALID` 401、`TOKEN_REUSED` 401（旧令牌二次使用，视为泄露，撤销该用户全部会话）。

#### API-3 GET / POST /admin/users （CT-10）

查询或创建用户。仅 SysAdmin 可调用。

GET 参数：`role`、`dept`、`status`、`cursor`、`limit`。

POST 请求：`username`、`name`、`dept`、`role`（reviewer / approver / librarian / observer）、`clearance`。

响应 201：`user_id`、`status=active`。

错误：`ACL_DENIED` 403、`VALIDATION_FAILED` 400（角色不在枚举内）。

约束：不得创建 `role=approver` 且 `clearance=restricted` 以外的组合例外；一人可有多个角色，但同一任务上撰写人与终审人不得相同，该校验在 API-11 执行。

### 3.2 审查任务

#### API-4 POST /reviews （CT-2、CT-8）

> **范围说明（2026-11-10 收窄）**：`task_type` 本期仅开放 `qa`；`formal` 枚举保留但一律按范围外处理（二期候选）；`profile_version` 仅 formal 需要。

发起条款问答或正式审查。

| 参数 | 位置 | 必填 | 说明 |
|---|---|---|---|
| `task_type` | body | 是 | `qa` / `formal` |
| `scope` | body | 是 | 条款 ID 数组，1 至 50 条 |
| `supply` | body | 是 | `self_hosted` / `managed_pinned` / `managed`；**`inference_scope` 不接受客户端传入，由服务端按供给档派生** |
| `profile_version` | body | formal 必填 | 业务事实快照版本 |
| `index_version` | body | 否 | 缺省用当前 active |
| `answer_lang` | body | 否 | `zh`（默认）/ `en`；仅 `task_type=qa` 生效，`formal` 忽略。非法值返回 `VALIDATION_FAILED` 400 |
| `Idempotency-Key` | header | 是 | ULID |

响应 202：`task_id`、`status=created`、`queue_position`（本机推理并发为 1，非 0 表示排队中）、`stream_url`。

`task_type=qa` 时，响应体在本任务字段之外同步返回问答结果：

| 字段 | 类型 | 说明 |
|---|---|---|
| `answer` | 字符串 | 抽句式回答：固定模板 + 命中原句，不由生成模型改写；模板与片段语种随 `answer_lang` |
| `citations[]` | 数组 | 每条含 `ref_id`、`provision_id`、`doc_id`、`version_no`、`page_no`、`char_start`、`char_end`、`lang`、`span_text`、`span_hash`、`translations[]`；`lang` 与 `doc_id` 随 `answer_lang` 取对应语种一侧 |
| `citations[].translations[]` | 数组 | 本期恒为 `[]`：语种由 `answer_lang` 单一决定，不再在单条引用内混排中英对照（字段保留以兼容历史记录的回放） |
| `warnings[]` | 数组 | 数据侧提示，如 `zh_unavailable:<provision_id>`（中文模式下命中的条款无中文译文） |
| `intent` | 字符串 | `knowledge` / `chitchat` |

检索为空时 `citations=[]`，`answer` 为固定拒答文案，不得用先验知识补全。`citations` 中每条引用都必须先通过 CT-3 的单条回验才可返回。

答案与引用不在同一条响应里混排两种语言：

- `answer_lang=zh`（默认）：`answer` 为中文模板 + 中文字段原文；`citations[].lang=zh`，锚点指向中文译版块（由命中英文块的 `pair_id` 反查），`doc_id` 为中译本。
- `answer_lang=en`：`answer` 为英文模板 + 英文原文；`citations[].lang=en`，锚点指向英文原版块。
- `zh` 模式下命中条款缺中文译文：返回「命中条款尚无中文译文，请切换英文版」类拒答文案，`citations=[]`，`warnings[]` 记 `zh_unavailable:<provision_id>`；不得表述为「未检索到」。

错误：`PROFILE_MISSING` 400、`SUPPLY_NOT_ALLOWED` 422（`formal` + `managed`）、`INDEX_NOT_ACTIVE` 409、`IDEMPOTENCY_CONFLICT` 409、`ACL_DENIED` 403、`GPU_UNAVAILABLE` 503（显存切换失败，可重试）。

约束：`scope` 超过 50 条须拆多次调用，服务端不自动拆——自动拆会让「一次任务」与「一个 finding」的对应关系丢失。**`inference_scope` 若出现在 body 里，服务端忽略并写审计告警**：客户端能改作用域，`local_single_gpu` 的 draft 机制就绕过去了。

#### API-5 GET /reviews/{id} （CT-2）

查询任务状态与已有 finding 列表。

响应 200：`task_id`、`status`、`profile_version`、`supply`、`inference_scope`、`queue_position`、`findings[]`（含 `finding_id`、`provision_id`、`verdict`、`signoff_status`、`signoff_eligibility`）、`created_at`、`finished_at`。

`task_type=qa` 时另返回 `citations[]`，内容取自 `cot_chains` 中 `step_type=E` 的 `anchors_json`；无引用时为 `[]`。引用字段与 API-4 相同（含 `translations[]`，本期恒为 `[]`；语种取落库时的 `answer_lang`；回放时从落库锚点重建，不重新检索）。

`task_type=ingest`（API-18 的异步入库任务）时 `findings=[]`、`steps=[]`，另返回 `document`（`doc_id`、`version_no`、`status`、`index_status`、`index_version`、`active_version`、`parser`、`page_count`、`text_layer_ratio`），`queue_position` 表示入库写队列中等待的任务数。任务终态 `failed` 时 `business_code` 给出失败原因。

错误：`NOT_FOUND` 404、`ACL_DENIED` 403。

#### API-6 GET /reviews/{id}/stream （CT-2）

SSE 流式返回链路进度。事件格式见 1.5。

错误：任务已终态返回 409 `TASK_FINISHED`，客户端应改用 API-5 拉取。

#### API-7 POST /reviews/incremental （CT-4）

语料更新后触发增量复审。

请求：`doc_id`、`new_version_no`、`affected_provisions`（数组）。

响应 202：`task_id`、`stale_findings[]`（受影响的旧 finding）。

规则：旧 finding 只标 `stale`，不覆盖；响应必须返回受影响清单，否则调用方无法通知审查员。

#### API-8 GET /cot/{finding_id} （CT-8）

> **范围说明**：CoT 完整链仅内部角色可见（R-9 口径）；QA 引用回放照常。

获取完整推理链。仅 reviewer 与 approver 可调用。

响应 200：`finding_id`、`steps[]`（`step_no`、`type`、`payload`、`anchors`、`validator_result`）、`invalidated_at`（作废时间，可为空）。

错误：`ACL_DENIED` 403（observer 调用即返回此码，不返回摘要）、`NOT_FOUND` 404。

#### API-9 POST /findings/{id}/signoff （CT-8）

> （产品范围外·二期候选，本期不开放）

审查员签署。

请求：`row_version`（必填）、`comment`（可选，≤500 字）。

响应 200：`finding_id`、`signoff_status=signed`、`signed_at`、`new_row_version`。

错误：`ROW_VERSION_CONFLICT` 409、`ACL_DENIED` 403（非本人经手）、`VALIDATOR_NOT_PASSED` 422（存在未通过的校验项）。

**无批量版本**：请求体不接受数组。

#### API-10 POST /findings/{id}/dispute （CT-8）

> （产品范围外·二期候选，本期不开放）

改写判定。旧记录标 `superseded`，新记录另起。

请求：`new_verdict`、`reason`（必填，≥20 字）、`evidence_refs`（必填，至少一条）。

响应 201：`new_finding_id`、`superseded_finding_id`。

错误：`VALIDATION_FAILED` 400（原因为空或过短）、`ACL_DENIED` 403。

#### API-11 POST /findings/{id}/finalize （CT-8）

> （产品范围外·二期候选，本期不开放）

终审。全系统唯一终审入口。

请求：`row_version`、`decision`（`approve` / `return`）、`comment`（`return` 时必填）。

响应 200：`finding_id`、`signoff_status=finalized`。

错误：`SELF_REVIEW_FORBIDDEN` 403（终审人 = 撰写人）、`ROW_VERSION_CONFLICT` 409、`ACL_DENIED` 403。

#### API-12 POST /ledger/export （CT-8）

> （产品范围外·二期候选，本期不开放）

导出整改清单或验证交接包。

请求：`type`（`remediation` / `verifier`）、`scope`（任务 ID 或日期区间）、`format`（`xlsx` / `csv` / `pdf`）。

响应 200：文件流，`Content-Disposition` 带文件名。

硬约束：`type=verifier` 时导出内容**不得含 CoT、不得含 `span_hash`**；导出前服务端执行剥离断言，断言失败返回 500 `EXPORT_ASSERTION_FAILED`。

### 3.3 整改台账

#### API-13 GET /gaps （CT-8）

> （产品范围外·二期候选，本期不开放）

查询整改台账。参数：`status`、`owner`、`due_before`、`cursor`、`limit`。

响应 200：`items[]`（`gap_id`、`finding_id`、`required_action`、`evidence_needed`、`owner`、`due_date`、`status`）、`next_cursor`。

#### API-14 PATCH /gaps/{id} （CT-8）

> （产品范围外·二期候选，本期不开放）

更新整改状态。请求：`status`（`open` / `in_progress` / `closed` / `waived`）、`comment`（`waived` 时必填）、`row_version`。

错误：`ROW_VERSION_CONFLICT` 409、`VALIDATION_FAILED` 400。

约束：`waived` 必须由 approver 操作并留理由；不允许批量关闭。

### 3.4 检索

#### API-15 GET /provisions/search （CT-1）

三通道检索。

参数：`q`（必填，1 至 2000 字）、`channels`（逗号分隔，默认 `dense,sparse,sql`）、`top_k`（默认 20，上限 100）、`corpus_type`、`effective_at`、`lang`。

响应 200：`candidates[]`、`fused[]`、`reranked[]`、`sparse_disabled`、`empty_reason`。

错误：`ACL_SCOPE_MISSING` 400（网关未注入即拒绝）、`INDEX_NOT_ACTIVE` 409。

说明：`empty_reason=acl_filtered` 与 `no_match` 必须区分展示——前者是权限问题，后者是语料问题，处理方式不同。

#### API-16 GET /provisions/{id} （CT-1）

条款原文与元数据。

参数：`version_no`（可选，缺省取覆盖当日的版本）。

响应 200：`provision_id`、`section_no`、`obligation`、`applicability_condition`、`text_original`、`page_no`、`effective_from/to`、`mappings[]`、`related_guidance[]`。

错误：`NOT_FOUND` 404、`ACL_DENIED` 403。

#### API-17 POST /retrieval/test （CT-1）

召回测试台。

请求：`query`、`role_view`（模拟角色，用于验证 ACL）、`config`（切分版本、嵌入版本、重排开关）。

响应 200：`hits[]`、`latency_ms`、`config_echo`、`acl_scope_used`。

约束：`role_view` 只允许 admin 与 approver 使用；普通审查员调用返回 403。测试结果不写台账。

### 3.5 文档与语料

#### API-18 POST /documents （CT-9）

上传文档。`multipart/form-data`。

字段：`file`（必填）、`doc_id`（必填，业务编号）、`corpus_type`、`dept`、`clearance`、`doc_type`、`effective_from`、`effective_to`、`index_mode`。

`index_mode` ∈ {`full`（默认）, `display_only`}。`display_only` 表示该文档只作引用对照的显示层：落 SQLite 与对象存储页文本，不写向量库，检索不可见（CT-4 显示层构建）。

响应 202：`task_id`、`doc_id`、`version_no`、`status=uploaded`、`file_hash`、`duplicate=false`、`queue_position`（入库写队列中等待的任务数，0 表示无其他任务）、`status_url`（值为 `/reviews/{task_id}`）。解析、切分与建索引由写队列串行执行；完成后任务 `status=succeeded`，文档 `status=published` 且 `index_status=active`（`display_only` 时为 `display_only`）。

重复上传（同 `doc_id` + 同字节）返回 200：已有 `doc_id`、`version_no`、`status`、`index_status`、`active_version`、`duplicate=true`，不新建任务、不重复排队。

处理失败：任务 `status=failed`、`business_code` 记失败原因（OCR 失败统一为 `ocr_failed`），文档 `status=failed`。**受理成功不代表入库成功**，调用方必须以任务终态为准。

错误：`VALIDATION_FAILED` 400（元数据缺项或 `index_mode` 非法）、`DOC_TOO_LARGE` 413、`MALWARE_DETECTED` 422、`IDEMPOTENCY_CONFLICT` 409。

说明：`duplicate=true` 表示同哈希已存在，返回已有记录，不新建版本。

#### API-19 GET /documents （CT-9）

列表。参数：`corpus_type`、`dept`、`status`、`cursor`、`limit`。

响应 200：`items[]`、`next_cursor`。

#### API-20 GET /documents/{id}/versions （CT-9）

版本链。响应 200：`versions[]`（`version_no`、`status`、`file_hash`、`published_at`、`superseded_by`、`index_version`）。

#### API-21 POST /documents/{id}/publish （CT-9）

发布并触发索引构建。

请求：`version_no`、`confirm_token`。

响应 202：`doc_id`、`version_no`、`status=published`、`build_task_id`。

错误：`DOC_HASH_MISMATCH` 409、`CONFIRM_TOKEN_INVALID` 400、`VALIDATION_FAILED` 400（解析未通过质量闸门）。

#### API-22 DELETE /documents/{id} （CT-9）

下架（软删）。请求：`reason`（必填）、`confirm_token`。

响应 200：`doc_id`、`deleted_at`、`index_removal_task_id`。

约束：原件保留 30 天；审计与历史 finding 引用的证据定位不受影响。

#### API-23 GET /mappings （CT-9）

查询 P&P 映射。参数：`provision_id`、`mapping_type`、`stale`。

响应 200：`items[]`（`pnp_section_id`、`provision_id`、`mapping_type`、`confirmed_by`、`confirmed_at`、`stale`）。

#### API-24 POST /mappings （CT-9）

人工确认映射。请求：`pnp_section_id`、`provision_id`、`mapping_type`、`comment`。

响应 201：`mapping_id`、`confirmed_by`、`confirmed_at`。

错误：`ACL_DENIED` 403（非 librarian 或 approver）、`CONFLICT` 409（同组合已存在）。

#### API-25 POST /mappings/suggest （CT-2）

模型提议映射，不落库。

请求：`provision_id`（或 `pnp_section_id` 之一）、`top_k`（默认 5）。

响应 200：`suggestions[]`（`candidate_id`、`score`、`rationale`、`suggestion_id`）、`model_fingerprint`。

约束：响应必须含 `model_fingerprint`；`suggestion_id` 仅供后续人工确认时引用，服务端不留存模型理由的原文超过 7 天。

### 3.7 评测与运维

#### API-29 POST /eval/run （CT-10）

触发评测。请求：`set_id`、`config`（切分版本、嵌入版本、重排开关、prompt 版本）、`note`。

响应 202：`run_id`、`config_hash`。

错误：`CONFLICT` 409（同 `config_hash` 正在运行）。

#### API-30 GET /eval/results （CT-10）

查询结果。参数：`run_id`、`metric`、`since`。

响应 200：`items[]`（`run_id`、`metric`、`value`、`config_hash`、`model_version`、`created_at`）。

约束：缺 `config_hash` 的结果不返回——不可复现的结果没有比较价值。

#### API-31 GET / POST /admin/models （CT-10）

模型与提示词登记。

GET 响应：`items[]`（`snapshot_id`、`role`、`supply`、`inference_scope`、`provider`、`model_name`、`weight_hash`、`ctx_limit`、`status`、`deployed_at`）。

POST 请求：`role`（gen / embed / rerank）、`supply`、`inference_scope`、`provider`、`model_name`、`weight_hash`、`ctx_limit`、`prompt_version`（gen 必填）。

响应 201：`snapshot_id`、`status=registered`。

约束：无 UPDATE 接口；激活走 `POST /admin/models/{id}/activate`（本文件未单列，属同一契约，动作写审计）。`weight_hash` 变化而 snapshot 未新增时，finding 发布被阻断。

**本机档位的两条额外约束**：① `inference_scope=local_single_gpu` 时 `ctx_limit` 必填且不得超过该卡可承载上限（一期为 4096）；② 同一 `role` 在 `local_single_gpu` 下**只允许一个 active**——一张卡上不可能常驻两个生成模型，允许登记多个只会让「当前到底跑的哪个」变成不可回答的问题。切换 active 时旧 snapshot 自动转 `standby` 并写审计。

#### API-32 POST /admin/backup （CT-10）

触发快照。请求：`targets[]`（`sqlite` / `objects`）。

响应 202：`backup_id`、`started_at`。

#### API-33 POST /admin/restore-drill （CT-10）

恢复演练。请求：`backup_id`、`rebuild_index`（布尔，必须为 true 才算完整演练）。

响应 202：`drill_id`。完成后写审计，含 `recall_at_5` 与是否达基线。

约束：`rebuild_index=false` 的演练不计入 RTO 达标。

#### API-34 GET / POST /admin/egress/policy （CT-10）

出域策略。GET 返回白名单、DLP 规则、通道开关状态。POST 请求：`allowlist[]`、`dlp_rules[]`、`channel_enabled`。

响应 200：`policy_version`、`effective_at`。

错误：`ACL_DENIED` 403（非 SysAdmin）、`CONFIRM_REQUIRED` 428（未带二次确认）。

#### API-35 GET /admin/egress/logs （CT-10）

出域日志。参数：`task_id`、`verdict`、`since`、`cursor`。

响应 200：`items[]`（`log_id`、`endpoint`、`purpose`、`payload_hash`、`dlp_verdict`、`created_at`）、`next_cursor`。

约束：只读，无删除接口；仅 approver 与 SysAdmin 可读。

#### API-36 POST /admin/cloud-channel （CT-10）

云通道开关。请求：`enabled`（布尔）、`reason`（必填）。

响应 200：`enabled`、`effective_at`、`degraded_mode`（关闭后为 `read_only`）。

错误：`PRECONDITION_FAILED` 412（开启时准入项未齐备）。

#### API-37 POST /badcases （CT-8）

反馈登记。请求：`finding_id`、`reason_code`、`comment`。

响应 201：`case_id`、`triage_status=pending`。

约束：不直接进评测集；须经人工分诊后由 `POST /eval/run` 的 `set_id` 引用。

#### API-38 GET /metrics （CT-10）

Prometheus 抓取端点。响应为文本格式，含请求量、时延分位、缓存命中、回验失败率、检索空集率、**显存占用与 OOM 次数**。**不含任何业务正文与用户标识。**

#### API-39 GET / POST /admin/ocr-approvals （CT-11）

B 类扫描件 OCR 出域审批登记。GET 按 `doc_id` / `version_no` 查询审批状态；POST 登记份额审批。

| 参数 | 位置 | 必填 | 说明 |
|---|---|---|---|
| `doc_id` / `version_no` | body | 是 | 审批对象；按文档版本而非单页审批，逐页审批在 200 页的底稿上不可操作 |
| `page_range` | body | 是 | 如 `1-200` 或 `1-30,45-60`；空表示全部 |
| `corpus_type` | body | 是 | 只接受 `B_internal`；`C_ledger` 返回 `OCR_FORBIDDEN_CORPUS` |
| `approver_id` | header 派生 | — | 由令牌决定，不接受 body 传入 |
| `note` | body | 是 | 审批理由，写入审计 |

响应 201：`approval_ref`、`effective_at`、`page_range`。

错误：`ACL_DENIED` 403（非 approver）、`OCR_FORBIDDEN_CORPUS` 422、`DOC_VERSION_NOT_FOUND` 404。

约束：审批只对指定 `version_no` 有效，文档升版即失效——**不自动继承**。理由是扫描件升版往往整份重扫，页内容可能全变，继承审批等于把旧审批套到新文件上。

## 第 4 章 明确不提供的接口

| 不提供 | 理由 |
|---|---|
| 批量签署 | 批量通过会在一周内被用成默认操作 |
| 跳过校验 / 强制通过 | 校验失败只能作废或重抽 |
| 对外 CoT | 对外只经 API-12 且剥离 |
| 任意 SQL / 台账自由查询 | 结构化通道仅白名单视图 |
| 绕过网关直连模型 | 供应商凭据只存在于网关 |
| 以云端为准回写本地 | 一致性校验单向，本地为准 |
| 修改历史 finding 的接口 | 只能 dispute 生成新记录 |
| 删除审计或出域日志 | 只追加 |

## 第 5 章 版本与弃用

1. 路径版本 `/api/v1` 只在发生不兼容变更时升 `/api/v2`；兼容变更不升路径。
2. 新增可选字段不通知；新增枚举值必须在变更单中列出，客户端须容忍未知值。
3. 字段弃用先标 `deprecated` 并双写，保留两个里程碑后移除。
4. 错误码只增不改；废弃码继续返回至少两个里程碑。
5. 接口变更须走 CHG 变更单，并同步更新《契约》《验收标准》与 PRD 第 11 章。
