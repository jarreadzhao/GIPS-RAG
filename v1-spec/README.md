## 阅读顺序

- **第一次接触这个项目**：PRD 第 1 章（1.2 定位、1.5 明确不做）→ 2.5.2.1（8 GB 显存的边界）→ 第 6 章（CoT 与三个硬机制）。
- **要写代码**：先读 `trae-instructions/` 的第 0 章与第 4 章（禁止事项），再按任务顺序做。
- **要评审**：PRD 附录 C（18 个组件各 4 个候选）与附录 D（13 项待确认），以及 `changes/CHG-20261107-02.md` 第 3 节「语义影响分析」。

## v1.1 与 v1.0 的差别（一句话版）

v1.0 按「有云 GPU、双人标注」设计；v1.1 改为**只有本机 8 GB 显卡、OCR 全云端、评测集 AI 标注**。连带后果是：生成模型从 32B 降到 8B、上下文压到 4k、并发只能是 1、时延门槛从 45s 放宽到 90s，以及新增 `draft` 机制（判定质量不达标时结论标草稿、不可签署）。详见 `changes/CHG-20261107-02.md`。

## 机检

两个脚本都随仓库提供，**在仓库根执行**：

```bash
python v1-spec/tools/spec_link.py --root v1-spec      # 四件套跨文件联检
python v1-spec/tools/prd_lint.py v1-spec/spec/PRD.md  # PRD 单文件结构细检
```

当前状态：`spec_link` 16 通过 / 0 失败 / 0 警告（78 条 AC、39 个 API、11 份契约、6 道阶段门）；`prd_lint` 0 失败 / 0 警告。

仓库已装 `.git/hooks/pre-commit`：联检失败直接拒绝提交。规格与代码必须同一个 commit，不拆。

## 开工前必须落实的三件事

1. **业务方确认 `draft` 交付是否可接受**（PRD 附录 D 第 13 条）。这是本期最大的未决项：不接受就得买 ≥ 24 GB 的卡，整个算力方案要重写。
2. **OCR 供应商零留存条款落地**（CT-11 硬规则）。没有合同条款，`page_image` 出域就不能开。
3. **抽检人必须是能做最终判断的资深审查员**。AI 标错的往往是边界项，只有资深审查员能发现；让实习生抽检等于没抽。
